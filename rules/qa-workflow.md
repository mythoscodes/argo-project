## 코드 품질 체크리스트

### 매 커밋 전 확인
- [ ] `pnpm build` 성공 (빌드 에러 0개)
- [ ] TypeScript 에러 0개 (`pnpm tsc --noEmit`)
- [ ] 미사용 import 없음

- [ ] `.env.local`이 `git status`에 없음

### 데모 시나리오 테스트 (Day 9)
```
1단계: 세션 생성 → 참여 코드 발급 확인
2단계: AI 퀴즈 생성 → 5문항 JSON 파싱 성공 확인
3단계: 수강생 참여 → 응답 저장 확인
4단계: 히트맵 → 실시간 갱신 확인 (2초 이내)
5단계: AI 코칭 → 코칭 제안 생성 확인 (3초 이내)
5-1단계: 재측정 → 델타 표시 확인
6단계: 수강생 리포트 → 자동 생성 확인
```

## 플립플롭 방지 규칙

에이전트가 이전 수정을 되돌리는 패턴 방지:

1. **수정 전**: 변경 사유를 TaskUpdate 또는 커밋 메시지에 기록
2. **이전 수정과 반대 방향 변경 시**: 팀 리드에게 확인 요청 필수
3. **디자인 변경**: `docs/design-changelog.md`에 변경 근거 + 참조 소스 기록
4. **프롬프트 변경**: 변경 전/후 AI 출력 비교 결과를 커밋 메시지에 포함

## 성능 기준

| 기능 | 목표 시간 | 측정 방법 |

| 페이지 로드 (강사 대시보드) | < 2초 | Lighthouse |

| 히트맵 갱신 (실시간) | < 2초 | Supabase Realtime 지연 |
| AI 코칭 제안 | < 3초 | API 응답 시간 |
| 수강생 퀴즈 응답 제출 | < 500ms | API 응답 시간 |
