## 1. 기획

### 1.1 설정한 사용자와 해결하려는 문제

#### 타겟 사용자

| 사용자 | 설명 |
|--------|------|
| **IT강사** | 코리아IT아카데미에서 Spring, React, Python, 정보보안 등 IT과목을 가르치는 강사 |
| **성인 수강생** | 취준생, 전직희망자, 직장인 등 국비지원으로 IT교육을 받는 성인 학습자 |
| **학원 운영자(원장)** | 수강생 유지율과 취업률을 관리하는 학원 경영자 |

#### 해결하려는 핵심 문제

**IT강사의 페인포인트:**
1. **수강생 수준 편차 극심** — 비전공 직장인과 컴퓨터공학 졸업생이 같은 반에 섞여 있어, 누구에게 맞춰 수업해야 할지 판단이 어려움
2. **실시간 이해도 파악 불가** — 30명 이상의 수강생이 코딩 실습 중일 때 누가 막혀있는지 눈으로 확인 불가
3. **수업 중 즉각적 대응 불가** — 이해도 격차를 수업 후에야 과제/시험으로 파악. 이미 뒤처진 수강생은 따라잡기 어려움

**성인 수강생의 페인포인트:**
1. **이해도 격차 방치** — 못 따라가도 질문하기 어려운 분위기. 조용히 뒤처지다 중도 포기 (IT교육 중도 포기율 30~50%)
2. **즉시 피드백 부재** — 내가 뭘 모르는지 모르는 상태로 수업이 진행됨
3. **학습 경로 불명확** — 어떤 개념이 약한지, 무엇을 보충해야 하는지 가이드 부족

**학원 운영자의 페인포인트:**
1. **중도탈락 = 매출 손실 + 기관평가 하락** — 국비지원 과정에서 수료율은 HRD-Net 기관평가의 핵심 지표
2. **강사별 강의 품질 편차** — 스타 강사 의존도가 높고, 신임 강사의 수업 품질 관리가 어려움
3. **교육 성과 정량화 한계** — 만족도 설문 외에 실질 역량 향상을 측정할 데이터 부재

### 1.2 솔루션의 핵심 기능

**EduLens는 IT 수업 중 실시간으로 수강생의 이해도를 분석하고, AI가 강사에게 교수법을 코칭하는 솔루션입니다.**

#### MVP 기능 (P0 — 데모 필수)

| ID | 기능 | 설명 |
|----|------|------|
| F1 | **수업 세션 관리** | 강사가 세션 생성 → 참여 코드 발급 → 수강생 모바일 접속 |
| F2 | **AI 코드 스니펫 퀴즈 자동생성** | 강사가 수업 주제 입력 → AI가 코딩 특화 퀴즈 자동 생성 ("이 코드의 출력은?", "버그를 찾아라" 등) |
| F3 | **수강생 실시간 퀴즈 응답** | 수강생이 모바일에서 퀴즈에 실시간 응답 (최소한의 UI) |
| F4 | **실시간 이해도 히트맵** | 응답이 들어올 때마다 개념별 이해도를 히트맵으로 실시간 시각화 (녹색=이해 / 빨강=미이해) |
| F5 | **AI 강사 코칭** | 이해도 데이터 분석 → "이 개념에서 60%가 약합니다. 보충 설명 권장" 같은 실시간 코칭 제공 |

#### MVP 기능 (P1 — 데모 권장)

| ID | 기능 | 설명 |
|----|------|------|
| F6 | **양방향 피드백 루프** | 보충 설명 후 재퀴즈 → 이해도 변화(델타) 시각화로 교수 개입 효과 확인 |
| F7 | **수강생 본인 학습 리포트** | 수업 후 자동 생성. 본인의 이해도 추이, 약점 개념, 추천 학습 경로 제공 |

#### MVP 기능 (P2 — 보너스)

| ID | 기능 | 설명 |
|----|------|------|
| F8 | **원장 경영 대시보드** | 반별 평균 이해도, 이탈 위험 수강생 자동 감지 |

#### MVP 추가 요소 — 멘토 연계 (최소)
- 강사 대시보드 히트맵에 **"상담 권장" 배지** 표시 (이해도 3주 연속 하락 수강생)
- KIT 멘토가 강사 대시보드를 읽기 전용으로 열람 가능 (별도 뷰 없음, 권한만 추가)
- 멘토 전용 대시보드/알림은 Phase 1.5에서 구현

#### 데이터 소스 (확정)
1. **코드 스니펫 퀴즈** (MVP 핵심) — 3가지 유형: 출력 예측 / 버그 찾기 / 빈칸 채우기. AI가 수업 중 코드 예제 기반 자동 생성
2. **코드 제출 + 자동 실행** — Phase 2 (Judge0 API 연동, Vercel Serverless sandbox 호환 리스크로 MVP 제외)
3. **코딩 실습 실시간 모니터링** — Phase 2 이후 로드맵

### 1.3 기대되는 개선점

#### 강사 관점
- **수업 중 즉각적 피드백 루프**: "어디서 막히는지" 실시간 파악 → 보충 설명 → 재측정 → 효과 확인
- **강사 역량 상향 평준화**: AI 코칭이 신임 강사에게도 베테랑 수준의 수업 운영 가이드 제공
- **퀴즈 출제 시간 절감**: AI가 수업 내용 기반으로 자동 생성

#### 수강생 관점
- **뒤처지는 순간 즉시 포착**: 조용히 이탈하기 전에 강사가 선제적으로 도움
- **본인 학습 리포트**: "이번 주 당신의 이해도: Python 기초 92%, 객체지향 65%. 추천: 상속 파트 복습"
- **수준별 맞춤 학습**: 히트맵 기반 그룹핑으로 개인 수준에 맞는 설명/과제 제공

#### 학원 운영 관점
- **중도 포기율 감소**: 이해도 하락 추세 조기 감지 → 상담 개입 → 수료율 향상
- **기관평가 개선**: 데이터 기반 교육 품질 관리 체계 = HRD-Net 기관평가 증빙 자료
- **마케팅 차별화**: "AI가 실시간으로 수강생 이해도를 분석하는 학원" = 경쟁 학원과 차별화

#### ROI 시뮬레이션 (수강생 30명, 6개월 과정 기준)
- 월 비용: 약 39만원 (구독 30만 + 수강생당 3,000원)
- 중도 포기 2명 방지 시: 400~1,000만원 매출 보전
- **ROI: 170~430%**

#### 2.2.5 기술 스택 아키텍처 검토 기록

프로젝트 초기에 다음 기술 스택 변경을 검토했으나, 공모전 완성도를 우선하여 기존 스택을 유지합니다.

**검토된 대안 스택:**
- FE: React (Next.js 대신)
- BE: Spring Boot + Kotlin (Supabase 대신)
- AI: Python 마이크로서비스 (MSA 구조)
- LLM: 로컬/임베디드 LLM

**기각 이유:**

| 기준 | 기존 스택 (채택) | 대안 스택 (기각) |
|------|-----------------|-----------------|
| MVP 일정 | **9일** | 25~30일 (3배) |
| 월 비용 (MVP) | **$6** | $111 (18배) |
| 2년 누적 비용 | **$8,000** | $30,000~36,000 (4배) |
| 유지보수 공수 | **월 6시간** | 월 18시간 (3배) |
| 배포 서비스 수 | **2개** (Vercel+Supabase) | 4~5개 |
| LLM 품질 | **상~최상** (API) | 중하 (로컬 8B) |
| 실시간 기능 | Supabase Realtime (0.5일) | WebSocket 직접 구현 (3~4일) |
| 완성 확률 | **높음** | 낮음 |

**Spring Boot + Kotlin 시너지**: KIT가 Spring을 가르치므로 "자기 학원 기술로 만든 솔루션"이라는 스토리가 가능하지만, 완성도 리스크가 너무 큼. Phase 2 로드맵에 "Spring Boot 백엔드 전환"으로 명시하여 어필.

> **핵심 원칙**: "완성된 모놀리스 > 미완성 MSA" — 공모전에서는 작동하는 결과물이 아키텍처보다 중요

### 2.3 AI 모델 선택 옵션 (3가지)

Vercel AI SDK(`ai` 패키지)를 사용하면 **코드 1줄 변경으로 모델 전환**이 가능합니다. 상황에 따라 3가지 옵션 중 선택할 수 있도록 설계합니다.

```typescript
// Vercel AI SDK — 모델 전환이 1줄 변경
import { google } from '@ai-sdk/google';
import { anthropic } from '@ai-sdk/anthropic';
import { openai } from '@ai-sdk/openai';

// 환경변수로 모델 선택
const MODEL_MAP = {
  'gemini-3-flash':   google('gemini-3-flash'),        // 옵션 A
  'claude-sonnet':    anthropic('claude-sonnet-4-6'),   // 옵션 C
  'gpt-5.4-mini':     openai('gpt-5.4-mini'),           // 대안
};
const model = MODEL_MAP[process.env.AI_MODEL || 'gemini-3-flash'];
```

#### 옵션 A: 완전 무료 (기본 권장)

| 용도 | 모델 | 비용 |
|------|------|------|
| 퀴즈 생성 (F2) | Gemini 3 Flash | $0 |
| 이해도 분석 (F4) | Gemini 3 Flash | $0 |
| AI 코칭 (F5) | Gemini 3 Flash | $0 |
| 리포트 생성 (F7) | Gemini 3 Flash | $0 |
| **공모전 전체 비용** | | **$0** |

- **장점**: 비용 제로, 단일 모델로 구현 단순
- **단점**: Claude 대비 misconception 태그 정확도 약간 낮음
- **적합 상황**: 비용을 최소화하고 싶을 때, 공모전 데모 수준에서 충분

#### 옵션 B: 하이브리드 (품질-비용 균형)

| 용도 | 모델 | 비용 | 이유 |
|------|------|------|------|
| 퀴즈 생성 (F2) | **Claude Sonnet 4.6** | ~$2 | 핵심 차별화 기능, misconception 정확도 최상 |
| 이해도 분석 (F4) | Gemini 3 Flash | $0 | 패턴 분석은 Flash로 충분 |
| AI 코칭 (F5) | Gemini 3 Flash | $0 | 실시간 스트리밍, 코칭은 간결하면 충분 |
| 리포트 생성 (F7) | Gemini 3 Flash | $0 | 요약 수준이므로 Flash 충분 |
| **공모전 전체 비용** | | **~$2~3** |

- **장점**: 핵심(퀴즈)에만 최고 품질, 나머지는 무료
- **단점**: 2개 API 키 관리 필요
- **적합 상황**: 퀴즈 품질이 데모의 핵심일 때

| 용도 | 모델 | 비용 |

## 5. 데모 시나리오

### 핵심 데모 플로우 (Python 기초 수업)

**1단계 — 수업 시작**
> 강사가 "Python 반복문" 세션을 생성하고 참여 코드를 화면에 표시

**2단계 — AI 퀴즈 자동 생성**
> 강사가 "for문, while문, 리스트 컴프리헨션" 입력 → AI가 코드 스니펫 퀴즈 5문항 자동 생성
> 예: "다음 코드의 출력은? `for i in range(3): print(i*2)`"

**3단계 — 수강생 응답**
> 30명 수강생이 모바일에서 실시간 응답

**4단계 — 이해도 히트맵**
> 응답이 들어올 때마다 히트맵이 실시간 갱신
> "for문 기초: 90% 이해(녹색) / 리스트 컴프리헨션: 40% 이해(빨강)"

**5단계 — AI 강사 코칭**
> AI: "리스트 컴프리헨션에서 40%가 이해 부족. 일반 for문→리스트 컴프리헨션 변환 예시로 보충 설명 권장"
> 강사가 보충 설명 후 재퀴즈 → 이해도 65%로 상승 (델타 +25%)

**6단계 — 수강생 학습 리포트**
> 수업 종료 → 수강생에게 자동 리포트: "이번 수업 이해도: for문 95%, while문 80%, 리스트 컴프리헨션 65%. 추천: 리스트 컴프리헨션 보충 학습"

### 코리아IT아카데미 과정별 퀴즈 예시

## 6. 심사위원 예상 Q&A

| 질문 | 답변 |
|------|------|
| "코딩 수업에서 이해도를 어떻게 측정?" | 코드 스니펫 기반 퀴즈 + 코드 실행 결과. 오류 패턴을 AI가 분석 |
| "기존 LMS와 차이점?" | LMS는 사후 성적 관리. EduLens는 수업 중 실시간 이해도 → 강사 즉시 대응 |
| "NCS 평가가 이미 있는데?" | NCS는 단원 끝 총괄평가, EduLens는 수업 중 형성평가. 대체가 아닌 보완 |
| "IT학원에서만 쓸 수 있나?" | IT학원에서 시작하지만 엔진은 범용. 기업교육, 대학 강의로 확장 가능 |
| "AI가 교수법을 코칭할 수 있나?" | 주관적 평가가 아닌 데이터 기반 제안. "60%가 이 개념에서 약합니다"는 사실 기반 |
| "프라이버시 문제?" | 익명화 기본 모드. 원장 대시보드는 통계만 표시, 개인 식별 없음 |
| "멘토 시스템과 어떻게 연계?" | 강사 대시보드의 이해도 데이터를 멘토가 상담에 활용. MVP는 "상담 권장" 배지, Phase 1.5에서 멘토 워크벤치로 확장. 수강생 동의 기반, 요약 수준만 공유 |
| "멘토 없는 학원에서도 쓸 수 있나?" | 핵심은 강사 AI 코칭. 멘토 연계는 확장 레이어. 담임/취업담당관 체계가 있는 모든 학원에 적용 가능 |
